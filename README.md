# Свояк — Docker + Render

Готовые исходники самостоятельной версии игры. Интерфейс сохранён; Cloudflare D1, ChatGPT Sites и вход через ChatGPT больше не требуются.

- Ведущий: один административный аккаунт с паролем, редактор вопросов, комнаты, табло, оценка ответов и корректировка счёта.
- Игроки: приглашение по секретной ссылке, имя и большая кнопка. До 24 игроков в комнате.
- Сервер: Node.js 22, HTTP API и WebSocket.
- Хранилище: отдельная PostgreSQL 17, автоматические версионированные миграции.
- Готовый пакет: 25 вопросов. Есть импорт/экспорт JSON.

## Быстрый деплой на Render через Docker

В архиве есть `render.yaml`: он описывает Docker Web Service и отдельную PostgreSQL. Docker Compose нужен только для локального запуска — Render использует Dockerfile и Blueprint.

### 1. Загрузите проект в GitHub

Распакуйте архив. Создайте пустой **приватный** репозиторий GitHub, например `svoyak`.
В корне репозитория должны находиться `Dockerfile`, `package.json`, `package-lock.json`, `render.yaml`, папки `client`, `server`, `migrations` и остальные файлы проекта.
Не загружайте ZIP как единственный файл и не добавляйте лишний уровень вложенности.

Через терминал, из распакованной папки:

```bash
git init
git add .
git commit -m "Initial Docker version of Svoyak"
git branch -M main
git remote add origin https://github.com/YOUR_USERNAME/svoyak.git
git push -u origin main
```

Замените `YOUR_USERNAME` своим именем. `.env` исключён из Git и Docker-контекста: реальные пароли в репозиторий не попадают.

### 2. Создайте Blueprint в Render

1. Откройте https://dashboard.render.com/.
2. Выберите **New → Blueprint**.
3. Подключите GitHub и выберите репозиторий `svoyak`, ветку `main`.
4. Render прочитает `render.yaml` и предложит создать приложение `svoyak` и базу `svoyak-db` во Frankfurt.
5. Введите **ADMIN_PASSWORD** — уникальный пароль ведущего, минимум 16 символов.
6. Проверьте стоимость двух ресурсов и подтвердите создание.

В конфигурации выбраны **платные** минимальные постоянные ресурсы: Web Service `0.5c-512mb`, PostgreSQL `0.1c-256mb` с диском 1 GB. Стоимость показывается Render перед созданием. Это не бесплатный деплой. Если такие ресурсы с теми же именами уже есть, поменяйте имена в YAML, включая ссылку `fromDatabase.name`.

`SESSION_SECRET` генерируется автоматически. `DATABASE_URL` связывается с внутренним адресом PostgreSQL автоматически. Пароль базы создавать вручную не нужно.

### 3. Дождитесь запуска

Render соберёт Docker-образ и запустит приложение. При старте сервер применит миграции и только после этого откроет порт. В логах первого запуска должны появиться:

```text
Migration applied: 001_initial.sql
Свояк: server ready
```

Проверка здоровья: `/healthz`, успешный ответ — `{"ok":true}`. Она проверяет и подключение к базе.

Откройте HTTPS-адрес приложения `https://...onrender.com`, который покажет Render. Войдите с `ADMIN_PASSWORD`. Никакой отдельной регистрации не нужно.

### 4. Проверьте игру с двух устройств

1. Создайте комнату. При необходимости отредактируйте готовые категории.
2. Нажмите **Пригласить игроков** и отправьте ссылку друзьям.
3. Игрок вводит имя; административный пароль ему не нужен.
4. Ведущий запускает игру, открывает вопрос и нажимает **Включить кнопки**.
5. Победитель нажатия появляется у ведущего. Оцените ответ: верный приносит стоимость вопроса, неверный снимает её.
6. После неверного ответа остальные снова могут нажимать. Уже отвечавший игрок блокируется до следующего вопроса.

Игроки могут открыть ссылку в другом браузере или на телефоне. После обновления страницы приложение восстановит игрока по токену в localStorage, пока данные браузера не очищены.

## Если хотите создать ресурсы вручную

Не используйте этот вариант параллельно с Blueprint: иначе получите два приложения и две базы.

1. **New → Postgres**: создайте PostgreSQL 17, имя `svoyak-db`, регион Frankfurt. Для постоянных данных выберите платный план.
2. **New → Web Service**: выберите репозиторий и **Language / Runtime: Docker**, тот же регион. Dockerfile — `./Dockerfile`, контекст — корень проекта. Команду Docker запуска оставьте пустой: она уже есть в Dockerfile.
3. Добавьте переменные окружения:

| Переменная | Значение |
| --- | --- |
| `DATABASE_URL` | **Internal Database URL** созданной PostgreSQL |
| `ADMIN_PASSWORD` | Уникальный пароль ведущего, не короче 16 символов |
| `SESSION_SECRET` | Случайный секрет, минимум 32 символа |
| `NODE_ENV` | `production` |
| `PORT` | `3000` |

Секрет можно сгенерировать локально: `openssl rand -hex 32`. Не вставляйте реальные секреты в исходники или README.

4. Health Check Path — `/healthz`. Persistent Disk для приложения не нужен.
5. Запустите деплой и пройдите проверку игры выше.

Используйте прямой внутренний адрес базы, а не PgBouncer в transaction mode: сервер использует отдельное соединение `LISTEN/NOTIFY` для обновления нескольких экземпляров приложения.

## Как сохраняются данные

Комнаты, игроки, вопросы, счёт и история хранятся в PostgreSQL. В контейнере приложения нет базы-файла, которую можно потерять при пересборке. Перезапуск приложения не удаляет данные. Удаление самого ресурса PostgreSQL удаляет хранилище; не удаляйте его при обновлении сайта.

В таблице комнаты есть номер версии. Изменение записывается только если версия совпадает с прочитанной. При одновременных нажатиях выиграть может только одна запись; остальные запросы получают уже закрытую кнопку. Побеждает запрос, первым успешно зафиксированный базой: интернет-задержки влияют на результат.

Ответы и административная ссылка не передаются игрокам. HTTP-заголовки ChatGPT не используются как доказательство входа. Ведущий получает подписанную HttpOnly-сессию на 24 часа; в production cookie передаётся только по HTTPS. Подбор пароля ограничен по IP.

WebSocket сообщает об изменениях без постоянного частого опроса. После обрыва клиент переподключается и загружает актуальное состояние из базы. Дополнительная сверка раз в 15 секунд страхует потерянные уведомления. После переподключения открытый вопрос и счёт сохраняются; сервер не принимает запросы со старым идентификатором этапа ответа.

Настройте резервное копирование PostgreSQL в Render и проверьте доступные условия восстановления вашего плана. Экспорт JSON из редактора сохраняет только пакет вопросов, а не комнаты и результаты.

## Локальный запуск через Docker Compose

Установите Docker с Compose. В корне проекта:

```bash
cp .env.example .env
```

В `.env` задайте:

- `ADMIN_PASSWORD` — минимум 16 символов;
- `SESSION_SECRET` — минимум 32 случайных символа;
- `POSTGRES_PASSWORD` — случайный пароль из букв и цифр (без символов, требующих URL-кодирования).

```bash
docker compose up --build -d
docker compose logs -f app
```

Откройте http://localhost:3000. Compose сам соберёт образ, поднимет PostgreSQL и дождётся её готовности. `DATABASE_URL` для Compose формируется из `POSTGRES_PASSWORD`; значение из `.env.example` для него не используется.

```bash
docker compose down
```

Эта команда остановит контейнеры и сохранит базу в именованном томе `postgres_data`. **Не добавляйте `-v`, если нужно сохранить данные.** Локальный HTTP запускается с `NODE_ENV=development`; Render должен использовать `production` и HTTPS.

## Обновления и миграции

Автоматический деплой отключён в `render.yaml`, чтобы случайный push не прерывал вечернюю игру. После изменения кода отправьте commit в GitHub, дождитесь проверок и выберите **Manual Deploy → Deploy latest commit** в Render. Лучше обновлять между играми: соединения на короткое время могут оборваться.

Миграции применяются автоматически при запуске с блокировкой PostgreSQL, которая защищает от одновременного применения. Старые применённые SQL-файлы нельзя редактировать: добавляйте новый файл в `migrations/`. Проверка контрольной суммы остановит запуск, если применённая миграция была изменена.

Для смены пароля обновите `ADMIN_PASSWORD` в Render. Для немедленного отзыва всех старых сессий одновременно замените `SESSION_SECRET`, затем перезапустите приложение. Пакеты и комнаты останутся в базе.

## Перенос пакетов из прежней версии

В прежнем сайте откройте редактор и нажмите **Экспорт**. В новом — **Импорт**, выберите JSON, затем создайте комнату. Активные комнаты, участники и результаты из Cloudflare D1 автоматически не переносятся.

## Проверки и ограничения

```bash
npm ci
npm run build
npm test
```

Сборка включает проверку TypeScript. Локальные тесты используют PostgreSQL-движок PGlite и проверяют миграции, 24 одновременных нажатия, скрытие ответов, права ведущего, повторную оценку, неверный ответ, старые запросы, HTTP-вход, CSRF, WebSocket и переподключение.

В `.github/workflows/check.yml` добавлены те же тесты на отдельной PostgreSQL 17 и сборка Docker-образа. Они выполнятся после загрузки проекта в GitHub. Для ручного запуска тестов с настоящей PostgreSQL задайте `TEST_DATABASE_URL`, указывающий **только на отдельную тестовую базу**: тесты очищают таблицу `rooms`.

В среде подготовки архива Docker-демон отсутствовал, поэтому полный Docker build и запуск на самом Render здесь не выполнялись. Сборка приложения и интеграционные тесты прошли. Производственная нагрузка и разные реальные мобильные сети не тестировались. Визуальная проверка этой версии браузером не выполнялась.

Это версия с одним административным аккаунтом. Все ведущие, знающие общий пароль, имеют доступ ко всем комнатам. Приглашения не имеют срока действия; не публикуйте их в открытом доступе. Бесплатные планы Render имеют ограничения: Web Service засыпает при простое, бесплатная PostgreSQL не предназначена для бессрочного хранения.

## Если что-то не запускается

| Симптом | Что проверить |
| --- | --- |
| `ADMIN_PASSWORD must have at least 16 characters` | Задайте достаточно длинный пароль в Environment |
| `SESSION_SECRET must have at least 32 characters` | Сгенерируйте длинный случайный секрет |
| Ошибка подключения к PostgreSQL | `DATABASE_URL`, готовность базы и совпадение регионов |
| После входа снова появляется форма | Открывайте HTTPS-адрес на Render; проверьте `NODE_ENV=production` |
| Игрок не может нажать | Игра запущена, вопрос открыт, ведущий включил кнопки, игрок ещё не отвечал |
| Не видны изменения | Проверьте соединение; обновите страницу; сервер и браузер должны использовать один домен |
| Docker не видит package-lock.json | В корень репозитория нужно загрузить всё содержимое архива |
| Имена ресурсов уже существуют | Измените имена в `render.yaml` перед созданием Blueprint |
